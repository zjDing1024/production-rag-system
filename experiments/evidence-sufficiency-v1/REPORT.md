# 证据门实测：协议失败不能算正确拒答

## 冻结与公平性

在首个模型请求前以提交 `3de638d` 冻结 12 个新英中问题、实际检索上下文、AI 助理逐题证据充分性标签（不是真人标注）
及 4 个诊断。第二个只读审阅（同一AI协作流程，非第三方公开预注册）确认了全部标签、真实 retrieval 与保存片段一致、删值操作准确。
数据按充分/相关不足/主题缺失三层排列，每层都有数值/非数值英中对。
明确问文档默认/how-to 的 `my/current` 反例是可答题；真实运行实例值不是。

普通问题调用真实 `GenerationPipeline.answer(query,k=3)`；没有把 gold 片段注入检索。
两臂实际供给 context 和 retrieval 逐对象相等，执行前后都验证。唯一策略改变是
是否先调用同一 Qwen 模型做证据判断。原生成器提示词、schema、预算和验证不变。
门和生成器均 temperature=0、seed=42、max_tokens=512，context=4096、CPU 4 线程。
on 多一次模型调用，不是 equal-compute 试验；单次 off→on 顺序和缓存可能影响时间。

门代码先于新题冻结，未用本轮答案调参数或更改校验。门要求 1–3 个确实出现在指定片段中的
逐字引用，或 `sufficient=false,evidence=[]`。非法输出、传输失败和合法不足判定严格分开。
同模型筛查不是独立验证者，`semantic_sufficiency=model_judgment_unverified` 保持明确。

## 主结果：10 个有候选问题，没有一个合法 gate 判定

| 观测 | Gate off | Gate on |
|---|---:|---:|
| 正常流程总数 | 12 | 12 |
| 原有无候选退出 | 2 | 2 |
| 实际生成器调用 | 10 | 0 |
| 门模型调用 | 0 | 10 |
| 被接受的正确且有支持答案 | 3 | 0 |
| 被接受的无依据/答非所问答案 | 4 | 0 |
| 生成器合同无效 | 3 | 0 |
| 门合同无效 | 不适用 | 10 |
| 新门合法证据不足判定 | 不适用 | 0 |

非空上下文中有 4 个充分、6 个不足。额外正确证据停止 **0/6**；额外合法误拒判定为 0，
但同时有 **4/4 充分题、6/6 不足题被门协议错误阻断**。这不是良好的误拒表现，更不是
证据判断能力提升。所有10个门的 raw JSON 都声称 `sufficient=true`，包括6个不足题。

充分题的已接受正确回答覆盖 **3/4→0/4**。baseline 第四题 a01-en 原始事实 `4093` 正确，
但没有引用，故不能计为被接受的正确回答。r01-en 将默认值当作真实运行值且缺引用；
r02-en 的文字表达了证据不足，但 `abstain=true` 配非空 `answer`，也没有通过拒答合同。
这些区别均写入助理逐题复核，不把 raw 正确、形式有效、最终服务答案混为一谈。

4 个 baseline 已接受错误分别是：把默认 `4093` 当实际阈值，把默认 `session` 当实际名称，
以及 PNG 的两项无依据/答非所问描述。门关闭了后续生成，因此最终未发出这些答案，
但关闭原因全是协议错误，**通过合法证据判定预防的错误为 0**。

两个棋盘问题在已有检索覆盖门退出，完全没有候选；不得算入新门的成功拒答或提升。
PNG 两题仍有检索候选，完整供给片段只含格式/图片示例，没有缩写展开，因此属于真正的
非空但不足输入。

## 原始判断、引用出处、所问论断是三层

所有14次 gate 调用（10主流程+4诊断）均正常完成 HTTP 推理，JSON可解析且 finish_reason=stop；
但至少一段引用无法逐字定位到它指定的片段，最终全为 `invalid_response`，不是网络错误。

对31个输出引用的**事后**诊断为：

- 14 个即使只归一空白也不出现在任何供给片段；
- 12 个与指定片段仅有空白差异；
- 3 个属于其他供给片段，不属于输出指定的 chunk ID；
- 2 个确实是指定片段的逐字子串；另有3个重复 ID/quote 对，与上述类别重叠。

这是故障分析，不是新的放宽校验实验。没有把归一化用于接受结果，没有删除坏引用、保留好引用
再冒充成功。即使修复引用格式，raw 判定仍把所有不足问题判为充分，语义问题不会因此解决。

## 同一个问题，只改变决定性证据

诊断询问 `MAX_FORM_MEMORY_SIZE` 的默认字节数。full 片段逐字来自 config.rst L335–365，
包含 `500_000`，旁边另有 `MAX_FORM_PARTS` 的 `1_000`。removed 版本仅删除唯一的
`500_000` 字节串，保留相同问题、ID、周边文字和所有其他数字。
独立审核确认删值后没有其他相同值表示或可用支持。

英中两组 full/removed 的 raw 判定全部为 `sufficient=true`，最终全部引用验证失败，
**合法且正确的诊断判定 0/4**。removed 版本还引用了逐字存在的 Default 字段中的 1_000，
但那是相邻另一个配置项，不能回答当前问题。这直接展示“引用真实存在”不等于“支持该论断”。
诊断没有调用回答生成器，因此不能声称系统把1000作为最终答案返回。

观察到的是本次 raw 布尔判定没有随关键证据变化而改变；由于四个输出均不满足合同，
不能宣称已经测得有效决策器的证据敏感性，也不能外推所有模型/问题都会如此。
该诊断事先设计已知，不是独立泛化测试。

## 结论

本轮把先前未验证的证据门变成了可运行、可否定的实验，结果是**当前小模型/提示词/逐字引用
组合不适合启用**。默认仍关闭。不以“没有输出错误答案”掩盖完全丧失服务能力。
下一轮如果研究引用稳健性，应另立协议和新题，分开测试出处定位、论断支持和回答生成，
不能把本轮事后归一化诊断写成已经获得的安全提升。
