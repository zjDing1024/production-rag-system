## 2. 三种流程，不做错误因果归因

**A：固定上下文文本 baseline。** 要求短回答和 `[S1]`；证据不足精确返回
`INSUFFICIENT_EVIDENCE`。

**B：固定上下文 schema 策略。** 共享相同证据、问题、采样参数，但输出说明改为
`answer/citations/abstain`，并开启原生 `response_format=json_schema`。
因此这是两套策略的实测比较，不是 grammar 的单变量消融。

**C：真实检索→生成。** 调用 `GenerationPipeline.answer(query,k=3)`，实际执行
现有 BM25、中文词典和覆盖门；只将它返回的片段传给本地模型，不注入 gold 上下文。
使用 adapter 自己的提示词、真实 chunk IDs 与输出校验。其上下文和提示词与 A/B
不同，不能将所有差异简单归因于“检索优劣”。

请求顺序在用例文件中固定：逐题 A→B，再逐题 C。每个组合只尝试一次，不重采样择优。
后续审阅脚本只核对保存记录；没有为了优化结果重新生成。

## 3. 分开计量形式、语义、拒答和运行状态

| 指标 | A：文本固定上下文 | B：schema 固定上下文 | C：真实 pipeline |
|---|---:|---:|---:|
| 流程数 | 12 | 12 | 12 |
| 实际模型调用 | 12 | 12 | 8 |
| HTTP/运行传输失败 | 0 | 0 | 0 |
| 完整 JSON 对象及字段类型合法 | 不适用 | 12/12 | 7/8 |
| 模型输出完整合同有效 | 10/12 | 11/12 | 5/8 |
| 可答题：事实正确且有支持 | 1/4 | 4/4 | 1/4 |
| 不足/缺失：合法模型拒答 | 8/8 | 0/8 | 0/4 进入模型的负例 |
| 检索门在模型前拒绝 | 0 | 0 | 4/8 负例 |
| raw 中无依据事实声称 | 0 | 7 | 3，其中1被截断校验挡住 |
| 无依据声称通过完整合同 | 0 | 7 | 2 |
| 语义正确且满足输出合同 | 8/12 | 4/12 | 5/12，含4个检索门拒绝 |

A 的唯一正确可答输出是中文 `S1: ... output ...`，事实正确但字面引用不合要求，
所以不进入最后一行的严格成功数。A 的 10 个合法形式里还包含 2 次可答题误拒。
B 的技术 API 标识符答案对英中文问题均算事实正确，不由此声称中文表达能力改善。

C 的 3 个 `invalid_response` **不是 3 次“证据不足”或 3 次网络错误**：
两个是 `abstain=true` 但 `answer` 为非空字符串 `"None"`；另一个是生成大量重复数字
后达到 token 上限，未完成 JSON。它在 raw 中已经编造重定向上限，所以同时存在
无依据生成和形式失败，只是没有作为最终 `answer` 返回。

人工语义审阅独立于合同有效性。引用 ID 必须属于供给集合，但“属于集合”并不证明
其内容能支持回答。`semantic_support` 在程序接口里仍为 `unverified`。

## 4. 关键失败原样摘录

- A，a01 英/中：`INSUFFICIENT_EVIDENCE`，但上下文明确有 `TestResponse.history`。
- B，r01 英/中：`{"answer": "2", "citations": ["S1"], "abstain": false}`。
  示例中的一次重定向不建立任何通用上限，更不支持 2。
- B，r02 英文：`{"answer": "None", "citations": ["S1"], "abstain": true}`。
  JSON 合法，跨字段拒答约定不合法。
- C，a01 英文：``The `Content-Type` header``；中文：`response.json`。
  两者的引用 ID 都存在，但没有回答所问的 redirect history。
- C，r01 中文：`最多允许跟随 1 次重定向`。
- C，r02 中文：`最多可以并行执行 1 个 CLI 命令`。
  上面两个错误上限通过形式校验，说明该校验不能防止无依据回答。

所有四个可答问题的正确事实都在 C 的**第一个供给块**中：history 在 testing.rst
L155–207；output 在 L234–285。因此这四题的生成失败不能解释成“gold 没召回”。
更多杂项上下文、长 chunk IDs、不同提示词等可能相关，但本轮未做控制实验确定原因。

## 5. 实际运行与保留范围

正式运行 UTC 2026-11-14 16:01:01 至 16:02:35，即 MYT 2026-11-15 00:01。

之后使用服务和客户端同进程启动方式，不绕过隔离或网络政策。

manifest 不含本机绝对路径；固定来源可追溯至已有许可文档。

## 6. 下一步边界

本轮交付是能运行且可审计的本地检索增强生成原型，不是可靠或生产就绪 RAG。
下一步可分别控制提示词与 grammar，比较短证据/完整检索块、缩短引用 ID，再设计
能识别证据不足的验证流程。必须另冻结问题并保留失败，不能继续用本轮开发题宣称泛化提升。
